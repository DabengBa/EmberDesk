# EmberDesk Backend API Data

Use this before changing `src/` server modules, endpoint behavior, or file-backed data.

## Read First

- `src/server-main.js` for middleware order, auth boundary, startup phases, and cleanup.
- `src/server-startup.js` for `setupPrivateEndpoints(app)`, deprecated redirects, and HTTP/HTTPS listen behavior.
- `src/users.js`, `src/user-storage.js`, `src/user-directories.js`, `src/user-migrations.js`, `src/user-auth.js`
- Owning route modules under `src/endpoints/`
- `.docs/tech/server-startup-orchestration.md`, `.docs/tech/user-module-split.md`, `.docs/tech/interaction-performance-indexing.md`
- Relevant tests under `tests/`

## Data Model Rules

- Canonical user data is file-backed under `globalThis.DATA_ROOT`.
- Per-user directories are generated by `getUserDirectories(handle)` from `USER_DIRECTORY_TEMPLATE`; do not hand-roll per-user paths when a directory helper exists.
- Characters are canonical PNG cards in `data/<user>/characters/*.png`.
- Chats, group chats, world info, settings, personas, assets, and secrets live under per-user directories.
- `node-persist` backs user account records via `src/user-storage.js`.
- `secrets.json` is managed by `SecretManager` and written atomically.
- Vectra indexes live under `directories.vectors/<source>/<collectionId>/<model>`; source, collection, and model names are part of lookup and purge semantics.
- Tokenizer model downloads and tokenizer caches use `DATA_ROOT/_cache`.
- `DiskCache` and `<user root>/_cache/character-index.sqlite` are derived acceleration only. They must self-heal or fall back to file-backed reads.

## Endpoint Rules

- Public user routes are mounted before `requireLoginMiddleware`; private APIs are mounted after it.
- `setupPrivateEndpoints(app)` in `src/server-startup.js` is the central private endpoint registry.
- Express 5 route compatibility is production behavior, not an experiment. Preserve method-preserving deprecated redirects, OAuth callback wrapping, CORS proxy target capture, user-file wildcard behavior, plugin routes, static MIME contracts, error handler placement, and final 404 behavior.
- Use existing validation helpers such as `validateAvatarUrlMiddleware`, `getFileNameValidationFunction`, `sanitize-filename`, `isPathUnderParent`, and route-specific validators before adding new path logic.
- For file writes that affect indexed characters, refresh or delete the character index through existing safe helpers.
- Chat mutations should mark character chat stats dirty instead of rebuilding every indexed row synchronously.

## High-Risk Areas

- Character mutation routes: create, rename, edit, edit-avatar, edit-attribute, merge-attributes, delete, import, duplicate, export.
- Chat saves include metadata integrity checks; an on-disk chat change can produce an integrity failure instead of overwriting blindly.
- World info deletion and cascade cleanup, especially character-bound world references.
- Secrets exposure through `allowKeysExposure` and `EXPORTABLE_KEYS`.
- User account flows, setup mode, session invalidation, SSO, and recovery.
- Config/data-root initialization before any module calls `getConfigValue`.
- Derived caches becoming accidental sources of truth.
- Legacy migrations in `src/user-migrations.js` are one-way migration logic from old `public/` and root paths, not generic copy utilities.

## Workflow

1. Identify the owning route/module and its focused tests.
2. Trace callers/callees with CodeGraph before changing shared helpers.
3. Preserve file-backed canonical writes and derived-cache invalidation.
4. Validate request bodies, filenames, and directory traversal with existing helpers.
5. Keep endpoint response shapes stable unless tests/docs/specs explicitly change them.
6. Update `.docs/db` or `.docs/tech` when user-visible behavior or architecture changes.

```powershell
bun run --cwd tests test:unit -- express5-route-compatibility.test.js --runInBand

bun run docs:check
```

Choose focused tests matching touched routes, then broaden only when the blast radius is shared.
