# 会话记忆（Chat Memory）设计（design proposal）

> 状态：**P1 + P2 已实现**（轮划分/后台摘要/原位替换/摘要卡/Inspector/设置）；P3（记忆面板/手写笔记/占用条）待做。
> 范围：仅**历史会话轮次内总结**。"提取到世界书"已暂缓，设计意图保留在附录备查。

## 目标

会话增长导致每次发送的 chat history token 持续上升。本方案用一条路径解决：

**按轮自动摘要（原位压缩）**：只保留最近 N 轮完整原文，更早的每一轮压缩成一条摘要，在原时间线位置替换——模型看到的仍是顺序连贯的叙事，只是旧轮变短了。

显式非目标：

- 不做向量检索 / embedding / RAG。
- 不做跨聊天记忆。
- 本阶段不做"提取到世界书"（见附录）。
- 不改写、不删除原始消息。摘要是投影，原文是权威。

## 核心概念

### 轮（turn）

- 一条 user 消息开启一轮；其后连续的 assistant（及非 user）消息归属同一轮，直到下一条 user 消息或聊天结束。
- 聊天开头、第一条 user 消息之前的 assistant 消息（开场白等）组成**第 0 组**，不占用"最近 N 轮"的计数，**默认视同钉住、永不自动摘要**（人设第一印象逐字保留）；仅当用户对其手动生成摘要时才压缩。
- 只有"已闭合"的轮计入窗口：至少包含一条 user 和一条 assistant。正在生成/未回复的当前输入不算一轮。

### 投影原则（不可变性）

- 摘要记录是**覆盖在原始消息上的投影**：原始消息永远保留在聊天存储中，摘要只决定"本轮发送时模型看到什么"和"聊天界面默认展示什么"。
- 这是整个方案的地基：它使**删除回填**（删掉新轮→旧轮自动展开恢复原文）、**点击查看详情**（原文仍在）、**分支安全**（分支不丢失任何内容）都成为免费性质。

### 摘要条目（turn summary）

每条轮摘要是一个独立记录，概念字段：

| 字段 | 说明 |
|---|---|
| 覆盖消息清单 | 本轮消息身份列表（持久化 `extra.id`，非位置序；见实现约束 1），用于失效检测 |
| 内容指纹 | 清洗后源文本（见实现约束 3）+ 激活 swipe 的哈希，判断"源内容是否变了" |
| 摘要正文 | 生成的摘要文本 |
| 状态 | `生效中` / `已展开`（轮回到窗口内，摘要休眠）/ `已失效`（源内容变动）/ `生成中` / `失败` / `人工编辑` |
| 生成时间、模型、prompt 版本 | 供追溯与"换 prompt 后重生成" |

### 整理游标

- 每个聊天维护一个"窗口边界"：最近 N 个已闭合轮为**完整轮**，更早的为**摘要轮**。
- 游标按消息身份追踪，不按位置序号——插入/删除/分支后仍能正确识别每轮是否被摘要覆盖。
- 默认 **N = 5**，全局默认 + 每聊天覆盖。

## 功能：按轮自动摘要

### 窗口规则

- 始终保留最近 5（可配）个完整轮的原文，既在聊天界面完整显示，也原文发送给模型。
- 第 6 轮及更早：聊天界面默认显示摘要文本；发送时该轮位置由摘要文本替代。
- 一轮一条摘要（"单轮内总结"）：不跨轮合并，保证每条摘要与单一轮的边界严格对应，失效粒度最小。

### 摘要生成时机

- **首选：后台空闲生成**。每轮回复生成完成后，检查哪些轮新滑出窗口，逐个发起一次不可见生成请求写摘要。不占下次发送的等待时间。
- **兜底：发送前不阻塞**。如果某轮已滑出窗口但摘要尚未就绪（生成失败、多设备同步间隙），该轮**保持原文发送**，并标记 `生成中` 继续后台补做。宁可临时多发 token，不为等摘要卡用户。
- **手动**：记忆面板提供"立即整理"——立即为当前所有应摘要而未摘要的轮补生成。
- **生成模型 = 后台模型**：原 `fallback_provider_model` 预设字段对外更名/语义扩展为「后台模型」——同一字段，语义从"主连接失败时的重试模型"扩为"失败重试 + 后台任务（摘要及未来其他维护生成）共用模型"。配置了后台模型 → 摘要走它；未配置 → 回退主连接模型。后台任务天然吃量大、质量要求低于正文，便宜模型是预期用法。
- **请求构成**：只带该轮原文 + 可配置摘要 prompt，不附角色卡/世界书/其他轮次/其他摘要。模板指令里允许 `{{char}}`/`{{user}}` 宏代入名字（属于指令文本，不算额外上下文），防人称漂移成"用户/助手"泛称。
- **与前台排队**：后台摘要等正常回复生成结束后才发起，不与在飞请求并发；「立即整理」期间新滑出的轮入队逐个消化。
- **重试熔断**：每轮摘要最多自动重试 2 次，仍败置 `失败` 静默等下个触发点（下次后台整理/立即整理），不对用户弹错。

### 显示层

- 摘要轮渲染为一张**紧凑摘要卡**：摘要正文 + "第 12 轮 · 已摘要"标识 + 覆盖范围。
- **点击查看详情**：卡片内就地展开该轮原始消息行，支持常规查看/编辑/swipe，再点收起。展开是临时查看，不改变窗口结构；一旦编辑或切 swipe 即触发摘要失效。
- 摘要卡样式与普通消息行明显区分（缩进/底色/图标），一眼可辨"这不是原文"。

### 注入层

- 摘要文本**原位替换**该轮在请求中的消息，位置不变、时间线不变。
- 注入角色可配（system/user/assistant），默认 system；包裹模板可配，提供 `{{char}}` `{{user}}` `{{turnIndex}}` 等宏，默认形如 `【早前剧情回顾】{摘要}`——让模型明确知道这是压缩内容而非现场对话。
- 摘要正文和其他注入内容一样经过 prompt 阶段正则管线，行为可预期。
- Prompt Inspector 中摘要轮以独立标识列出（区别于普通 chatHistory 条目），并能看到"该轮原文未发送"。

### 失效与恢复（stale 语义）

以下事件使覆盖到对应消息的摘要标记 `已失效`：

- 编辑消息正文
- 切换 swipe（激活 swipe 变了 = 指纹变了）
- 重新生成覆盖范围内的消息
- 删除轮内部分消息（覆盖清单对不上）
- 消息上下移动改变轮构成

失效后的行为：**该轮回退为原文发送**（投影没了就用真身），状态显示 `已失效`，后台自动重新生成新摘要。用户也可在面板手动点"重新生成"。

例外：**摘要被用户手动编辑过**的条目不自动覆盖——失效时提示用户选择"重新生成"或"保留人工版本"。

### 删除回填（自动展开）

- 用户删除最近的完整轮 → 窗口内完整轮数低于 N → **最近一个摘要轮自动恢复为原文显示与发送**，其摘要条目转 `已展开` 休眠（不删除）。
- 该轮未来再次滑出窗口时：内容指纹未变 → **直接复用旧摘要**；变了 → 重新生成。
- 删除摘要轮内全部消息 → 对应摘要条目一并清除。

### 与 token 预算的关系

- 轮数窗口是**主规则**；既有 token 预算是**兜底**。摘要也占 token，若摘要+保留轮仍超 `openai_max_context` 预算，沿用现有行为：从最老的消息开始丢弃（摘要在丢弃序列中同样按位置参与）。
- 不为记忆单设预算车道——按轮模型本身已经是有界的（每轮一条短摘要）。

## 功能：记忆面板（管理与可视化）

一个新的「记忆」面板，入口放工作区导航或聊天选项。三块内容：

### 占用可视化

- 顶部一条占用条：上下文预算分段 `系统提示 | 世界书 | 保留轮原文 | 摘要 | 回复预留`，悬停显示各段 token。
- 与 Prompt Inspector 预算条同源同数据；Inspector 显示"下一次发送"，面板显示"当前会话状态"。
- 摘要轮数量、待生成数、失效数给出计数提示。

### 条目列表

- 按时间序列出全部摘要条目：摘要正文、覆盖轮次/范围、状态（生效中/已展开/已失效/生成中/失败/人工编辑）、生成时间。
- 逐条操作：编辑正文、重新生成、删除（删除后该轮回退原文发送）、查看原文（展开覆盖消息）。
- 手写笔记：可新增不来自任何轮的常驻笔记（always-on，随聊天走）；**固定注入在 chatHistory 集合最顶部**（第 0 组开场白之后、第 1 轮之前），角色与包裹格式复用摘要配置（如 `【常驻记忆笔记】…`）。
- 「立即整理」按钮：手动触发一轮补摘要。

### 钉住消息

- 消息行新增「钉住」动作。**钉住锁定整轮**：一轮内任意消息被钉住 → 该轮不压缩为摘要、整轮原文发送——避免"半轮摘要概括了某回复、紧接着该回复原文又出现一遍"的碎片与重复注入。心智模型：钉住 = 该轮永远逐字在。
- **预算语义**：装配时先统计全部钉住轮与常驻笔记的 token 并**提前预留预算**，遍历到钉住内容时再释放并插入——保证"丢弃序列中最后被淘汰"真实成立（否则从新到老超支即停的截断循环根本走不到早期钉住轮）。
- 面板中集中查看/取消钉住。

## 与其他子系统的交互

| 子系统 | 约定 |
|---|---|
| Prompt Inspector | 摘要轮以独立标识出现在消息列表；被摘要替换的原文在 dropped/替换区可见——预览与实发严格一致 |
| 正则 | 摘要注入文本过 prompt 阶段正则；显示层摘要卡走普通渲染管线 |
| Swipe/分支 | 摘要指纹绑定激活 swipe；分支时显式拷贝 `chat_metadata.chat_memory` 并过滤为"覆盖消息全部落在分支截取范围内"的条目，游标自动重算（见实现约束 1） |
| 聊天导入导出/备份 | 摘要与游标随聊天元数据携带；导入无记忆数据的旧聊天 = 功能冷启动，逐轮补摘要 |
| 临时聊天 | 无持久化目标 → 按轮摘要禁用，退回纯 token 截断 |
| 多设备 | 摘要记录存在聊天元数据（服务端权威），各设备看到一致结果；摘要生成动作由当前打开该聊天的客户端执行——两客户端同时打开时后写胜出，可接受 |
| 生成失败恢复 | 摘要生成失败不阻塞任何发送；每轮最多自动重试 2 次，仍败标记 `失败` 等下个触发点，静默不弹错 |

## 边界与异常

- **聊天太短**（不足 N 轮）：无摘要需求，功能静默不动作。
- **第 0 组开场白**：独立组、不占 N 计数、默认视同钉住不自动摘要；用户可手动压缩。
- **窗口内轮被编辑**：原文轮照常编辑，无摘要牵涉。
- **摘要轮被展开查看时编辑**：允许，编辑后指纹变 → 摘要失效 → 回退原文 + 后台重生成。
- **一轮极长**（单轮就很大）：摘要照样生成；若单轮原文本身逼近预算，摘要收益更明显，不退化。
- **摘要文本被用户手动编辑过**：记为 `人工编辑`，自动重生成不覆盖人工版本（失效时提示用户选择重生成或保留人工版本+原文发送）。

## 实现约束与关键切入（技术评审补充）

以下 7 点来自对现有代码的核对，实现时必须遵守，否则按字面写就会踩坑。

### 1. 消息身份必须持久化（`extra.id`）

- 现状：前端 message uid 是内存 `WeakMap`（刷新即重算、不落盘）；后端 canonical chat 在消息无 id 时退化为 `hash(name + send_date + payload)`——编辑正文或切 swipe 都会令身份哈希变化；`createBranch` 不继承原聊天的 `chat_metadata`。
- 约束：新消息创建时写入 `extra.id`（UUID）；旧聊天加载时对缺失者惰性补齐。canonical 存储已原生优先读 `extra.id`，顺带让 DB 消息行身份在编辑后保持稳定。
- 分支：`createBranch` 显式拷贝 `chat_metadata.chat_memory`，并过滤为"覆盖消息全部落在 `chat.slice(0, mesId + 1)` 内"的摘要条目。

### 2. 后台摘要走旁路请求，不复用 `generateQuietPrompt` / `Generate('quiet')`

- quiet 路径会组装完整角色卡 + 世界书 + 全历史，修改 `extension_prompts`/`abortController`，触发全局生成事件——与"只喂当前轮原文"语义直接冲突。
- 约束：独立最小请求体（system 摘要模板 + user 该轮清洗后原文），`stream:false`、不带 tools，模型取后台模型（未配置→主模型），使用独立 `AbortController`；前台发送或切换聊天时立即 abort 在飞请求，绝不争抢前台连接。

### 3. 摘要源文本提取规则

- 轮内可能混入：`is_system` 工具调用卡 / `extra.tool_invocations` 中间记录、Reply Pipeline 前置步骤标签（`<tool>…</tool>` 转义块）、`extra.reasoning` 思维链。
- 约束：忽略 `IGNORE_SYMBOL` 消息与纯工具中间记录；剥离 reasoning 与管线步标签（把现有 prompt 侧剥离逻辑抽成共享纯函数）；`contentHash` 基于**清洗后文本 + 激活 swipe id** 计算，避免无关元数据变动导致误失效。

### 4. 原位替换的装配切入点

- 发送管线顺序：coreChat 过滤 → USER_INPUT/AI_OUTPUT 正则 → reasoning 注入 → **世界书扫描** → `setOpenAIMessages` → 深度注入（injection_depth）→ 从新到老扣预算（超支即停、记 dropped）。
- 约束：在 `coreChat` 正则/Reasoning 之后、进 `setOpenAIMessages` 之前（或其内部）把生效摘要轮折叠为单条消息对象，携带 `summaryMeta { turnIndex, summaryId, replacedMessages }`。
- **世界书扫描基于替换后序列**（或仅最近完整轮+摘要文本），防被压缩旧轮里的偶发词每轮幽灵触发条目。
- Inspector：摘要消息给独立标识（`chatSummary-turn-N` 而非 `chatHistory-k`），`replacedMessages` 记入 `summarizedEntries`（或 dropped 扩 `reason: 'summarized'|'budget'`），与超预算丢弃严格区分。

### 5. 钉住 = 锁整轮 + 预算预留

- 轮内任一消息被钉 → 整轮不压缩、原文发送（消除半轮摘要+半轮原文的重复注入）。
- 截断循环从新到老、超支即停：必须先对全部钉住内容与常驻笔记 `reserveBudget`，遍历到它们时 `freeBudget` 再插入——否则早期钉住轮在 break 前根本轮不到。

### 6. 显示层不改 `state.chat`/`mesid` 契约

- `messagesById`/`mesid`/`visibleMessageIds`/`scrollRestore` 全部锚定真实数组下标——摘要只在 React 渲染层映射为折叠组。
- 收起态：该轮起始位置渲染摘要卡；展开态：摘要卡 + 下方该轮真实消息行列表（天然保留 mesid/编辑/复制/swipe 能力）；窗口化锚点绑该轮首条 messageId。

### 7. 后台回写 CAS 校验

- 入队记录 `{ chatId, turnKey, coveredMessageIds, sourceContentHash }`；响应返回准备写 `chat_metadata` 时核对：
  1. 当前活动会话仍是 `chatId`（切聊天则丢弃结果）；
  2. 按 `coveredMessageIds` 重算 `sourceContentHash`，一致才置 `生效中`（期间被编辑/切 swipe → 丢弃或重排重试）；
  3. 前台流式生成中只更新内存态，等前台结束的 `saveChatConditional` 合并落盘，避免前后台并发保存冲突。

## 已决议项

- **摘要/后台任务模型**：用「后台模型」（`fallback_provider_model` 改名扩展：失败重试 + 后台任务共用；未配置回退主模型）。
- **摘要注入角色**：默认 system + `【早前剧情回顾】`包裹模板（均可配）。
- **摘要请求构成**：只喂当前轮原文 + 可配置摘要 prompt；不附角色卡/世界书/其他轮次/其他摘要；防人称漂移靠模板内 `{{char}}`/`{{user}}` 宏。
- **并发**：后台摘要排队，等前台生成结束后跑；「立即整理」期间队列逐个消化。
- **重试熔断**：每轮最多 2 次自动重试，仍败标 `失败` 静默等下次，不打扰用户。
- **手写笔记注入**：与摘要包裹同位置同角色，独立一条。
- **摘要语言**：随会话语言；摘要 prompt 模板在设置中完全可调（语言约束由模板文本控制）。

## 附录 A：暂缓方向——提取到世界书（备查）

暂缓，不是放弃。原始需求：用户手动触发，按**可配置 prompt** 对会话内容提炼，按**时间线**和**角色名**两类分别写入世界书条目。设计要点备查：

- 定位与自动摘要互补：摘要保"剧情连续性"，提取保"知识点固化"；产物是真正的世界书条目，复用现有关键词触发/预算/深度机制，不新建触发系统。
- 范围可选：已被摘要覆盖的区段（默认）/ 最近 N 轮 / 整个聊天。
- 条目形态：**时间线**→ 单条滚动"编年史"条目（追加合并更新，默认常驻）；**角色**→ 每个角色名一条条目（关键词=角色名+别名，提到才触发）。按条目名+来源标记匹配更新，不重复造条目。
- **不落暗箱**：提取结果先进预览列表，逐条可编辑/勾选/选目标书，确认后写入。
- 启用时机建议：P1–P3 稳定后作为独立功能评估，与"手写笔记晋升世界书"可考虑合并设计。

## 附录 B：参考——RisuAI HypaMemory 的可借鉴点

- 摘要列表而非单个滚动摘要；每条 summary 用消息身份清单记录覆盖范围（本方案的"覆盖消息清单"同源）。
- 按身份而非位置追踪 → 编辑/删除/分支后可检测"孤儿摘要"（本方案的失效语义）。
- 保留最新若干条原文不动（本方案的窗口规则）。
- 提前多压摊薄触发（本方案用"后台空闲生成"达到同效）。
- 刻意不借鉴：嵌入相似度检索（RAG，已排除）、摘要独立块注入（本方案选原位替换）。
