# 会话记忆（Chat Memory）设计

> 状态：P1/P2 轮摘要链路、摘要卡、Inspector 和全局设置已实现；下述当前会话面板为**已批准、待实现与验收**的范围。本次仅更新文档，不交付代码，也不将既有桥接能力等同于面板已上线。

## 目标与已实现基础

按轮自动摘要在原时间线位置替换旧轮，最近 N 个已闭合轮保留原文（默认 N = 5，默认关闭）。一条 user 消息开启一轮，至少包含 user 和 assistant 才是已闭合轮；首条 user 之前的开场组不自动摘要。原消息永远是权威，摘要只影响展示和发送投影，不改写或删除原文。

既有实现包含：轮划分、摘要有效性校验、后台最小旁路请求、原位替换、主聊天摘要卡及展开、删除新轮后的窗口回填、Prompt Inspector 的独立已摘要区、全局对话记忆设置。编辑、切 swipe、隐藏或删除覆盖消息后，无效摘要不能继续遮蔽原文。钉住任意消息使整轮保持原文；这不承诺突破上下文预算。

实现所有者仍为 `public/scripts/chat-memory-core.js`、`public/scripts/chat-memory-service.js`、生成装配与 React 主聊天投影。已有 `getContext().chatMemory.getView()` 和 `runImmediateConsolidation()` 不代表下文的新操作均已实现。

## 已批准：独立当前会话面板

### 入口与布局

- 工作区聊天选项菜单新增 `对话记忆`，与 `链路日志` 同级，打开独立 panel；不是 Settings 子页、主导航新增入口或 Wire Log 内嵌区。
- 仅管理当前打开的会话。面板明确当前对象，分为会话设置、轮次与只读摘要、执行历史；无跨会话浏览或批量管理。
- 空会话、无摘要、无历史分别显示可理解的空态；无持久化目标的临时聊天不伪造保存成功，不开放需要持久化的操作。
- 关闭、Escape 与键盘焦点返回遵循独立面板的可访问交互；窄屏保持操作可达，不用悬停作为唯一入口。

### 设置：继承、覆盖、恢复

- `/settings` 的对话记忆字段仍是全局默认。会话初始继承全局值，面板显示有效值及“继承全局”或“当前会话覆盖”的来源。
- 覆盖范围是既有记忆设置：开关、保留完整轮数、注入角色、摘要输出上限、摘要 prompt、包裹模板。覆盖只写当前会话元数据，不回写全局设置。
- `恢复继承` 删除会话覆盖，重新采用当时的全局默认，不将旧默认复制成固定值；不清空摘要、pin 或执行历史。
- 显式展示未保存、保存中、已保存、保存失败。失败保留草稿并允许重试；只有持久化成功才称已保存。主动关闭时确认是否丢弃未保存修改；独立发生的会话切换会关闭面板、丢弃草稿并通知用户。
- 后台模型沿用服务设置的 `fallback_provider_model`：设置了用后台模型，否则用主模型；共用 URL 和 key，不提供独立模型/凭据编辑器。调整模型仅影响之后的任务，不自动重写已有摘要。

### 轮次与操作

- 按轮查看原文/已 pin、已摘要、待生成、生成中、失效和失败等真实状态，摘要正文只读；查看原文沿用原消息能力。
- **单轮重总结**：仅针对所选可处理轮重新生成，校验当前消息身份及内容后才回写。失败不能让陈旧摘要继续生效，原文仍可发送。
- **仅失败轮重试**：只选择当前会话失败轮，不暗中变为全量重生成，不覆盖成功轮；没有失败轮时明确禁用或显示无待重试项。
- **pin 原文**：pin/unpin 锁整轮，不产生半轮摘要与半轮原文重复注入；pin 轮不参加摘要任务。pin 不是超出模型上下文仍必定发送的保证。
- 任务繁忙、前台生成中、不支持或无可处理轮时提供明确状态，阻止重复点击。后台工作不阻塞前台发送；缺失、失效或失败摘要回退原文。
- 本阶段不添加摘要编辑、摘要删除、手写笔记编辑/注入、使用量条或 token 占用可视化。不再把这些旧设想列为本次 P3 承诺。

### 执行历史与隐私

- 执行历史写入当前会话的 `chat_metadata.chat_memory`，不是浏览器临时列表；刷新、关闭重开后仍属于该会话。
- 最多保留最近 **50** 条，超过后移除最旧条目。记录操作、轮次标识、时间、可用的模型信息、结果及脱敏失败分类，足以区分成功、失败、取消等真实结果。
- **不记录原文、摘要提示词、完整请求/响应或原始错误**；不将可泄漏内容的错误字符串直接展示或持久化。历史不是摘要正文的副本，也不提供请求重放。
- 这不是 Wire Log。Wire Log 仍有自己独立的请求捕获与保存策略，本面板的最小历史不能被描述为关闭了全局链路日志正文捕获。
- 新分支只继承覆盖消息完整保留的有效摘要等既有记忆数据，**不继承执行历史**；分支历史从空开始，不将父会话执行视为分支已执行。

### 会话切换与保存一致性

- 会话切换时关闭面板并清除旧会话的临时选择、草稿及错误反馈；如果草稿被丢弃则通知用户，不把旧会话状态闪现为新会话结果。
- 前台开始或切换会话时取消旧后台请求；晚到响应不能写入当前新会话。摘要提交前校验会话身份、覆盖消息和源内容版本，不匹配则丢弃，不以成功显示。
- 原始消息及摘要、覆盖、执行历史跟随各自会话保存。内存更新、排队或请求结束不等于保存完成；保存失败应暴露可恢复状态。
- 不宣称已实现跨设备任务锁、冲突合并或后台服务常驻执行。现有摘要由打开会话的客户端调度，新增面板能力须用实现和测试证明。

## 验收工作流（待实现后执行）

1. 从聊天选项打开独立面板，确认与链路日志同级且只显示当前会话；短聊天、临时聊天及无历史状态有明确反馈。
2. 继承全局设置，在一个聊天覆盖并保存、刷新重开；另一个聊天不受影响。恢复继承后采用最新全局值，摘要与历史不被清空。模拟保存失败，草稿保留且不显示成功。
3. 查看只读摘要，对单轮重总结；制造失败后“仅失败轮重试”，成功轮不被重做。pin 后整轮使用原文；unpin 后按窗口和有效性规则恢复。
4. 操作记录刷新后可见，超过 50 条仅留最新 50；检查不含原文、提示词或原始错误。创建分支，符合条件的摘要保留而执行历史为空。
5. 在任务进行中切换会话，晚到结果不污染新聊天；未保存草稿被丢弃时应通知用户，返回原聊天只见真实保存结果。

文档校验 `pnpm run docs:check` 只证明语义引用和结构有效，不能当作以上 UI、任务与持久化验收通过。

## 保留边界

不做向量检索、embedding/RAG、跨聊天记忆或提取到世界书。摘要继续参与现有上下文预算，不能承诺摘要后永不截断。未来笔记、编辑器、使用量条需要独立批准，不属于本次交付。
