# Workspace Controller Retirement Plan

**Status: Waves 1–6 implemented in the workspace worktree.** For current ownership and startup order, see [Workspace Composition Root](workspace-composition-root.md).

## Target architecture

Keep one workspace and one implementation per operation. React owns interactive presentation: dialog visibility and focus, menu state, form events and previews. Existing domain modules own character operations, chat persistence and recovery, settings writes, and generation. `public/script.js` remains the workspace runtime entry, but owns only composition and lifecycle: it constructs and connects those owners, starts and stops workspace resources, and retains small forwarding exports only where a caller still needs them. Retire `public/scripts/dom-handlers.js` once its last handler is removed; do not copy the binder into a new module or React effect.

Move one write path at a time. External callers such as keyboard shortcuts and native features should call the same named commands as React instead of clicking hidden controls or writing its DOM. A command may have multiple callers, but only one owner executes it. Keep a compatibility host until its last actual use is replaced; remove it in that wave if it is no longer needed for rendering, serialization, focus, or a protected selector contract. State meant for one feature stays there; do not replace the old shell with a universal context or another state store.

Wave 4 extracted History commands and recovery coordination, keeping session and persistence authority in chat ops. Wave 5 consolidated settings revision observation and registration of prompt and generation owners. Wave 6 removed the shared binder and its shell context. Startup now awaits bootstrap directly; retained native browser effects and compatibility handlers are installed explicitly. `public/script.js` is still the composition root and retains live state and compatibility behavior; removing the binder does not imply that every root function has moved.

## What stays

- One React SPA and one workspace runtime entry. Keep existing server startup and native TypeScript, data layout, old-data normalization, and import/export compatibility. No new framework or dependency is needed.
- First-party event names and behavioral ordering, character-list and message-row identity selectors, composer IDs, macros and Regex semantics, and frontend-frame isolation. Shared native helpers such as motion and Cropper may remain when they have a caller; a native helper is not a second UI owner.
- Firefox 114 support, `user.css`, and global CSS with live consumers. Remove a stylesheet rule or bridge only when this migration eliminates its last consumer. No bulk CSS or library replacement.

## Definition of done

Each wave changes the owner and deletes the replaced path in the same change. Use the named focused tests and an isolated browser run for changed interactions; run the existing compatibility suite when shared selectors, macros, Regex, or rendering are touched. Update technical ownership docs as waves land; update semantic docs only if user-visible behavior changes. Rollback is a revert or prior deployment, not an in-product fallback.

The retirement is complete when `public/scripts/dom-handlers.js` and its startup call are gone, no React surface depends on a legacy DOM writer for the same interaction, and `public/script.js` no longer owns domain writes or view behavior. Remaining compatibility forwarders, native helpers, and diagnostics have concrete consumers. File counts, line counts, or the absence of all browser-side JavaScript are not completion criteria.
