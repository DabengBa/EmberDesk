# Page: Chat Workspace

## ID 解释

`page.chat_workspace` represents EmberDesk's main in-browser working surface after the workspace finishes loading. It covers the persistent shell that users stay in while switching characters, chats, and backgrounds. It does not cover installation, sign-in, or initial setup.

## Page Purpose

This page exists so a user can run their daily LLM workflow from one browser surface: choose a character, open or continue a chat, and adjust surrounding workspace context without leaving the main shell. A message beginning with `/` is ordinary chat text; no command shortcut is available.

## Page-Level Semantic IDs

- `feature.startup_bootstrap`: the visible loading experience between opening the workspace URL and reaching a usable surface.
- `feature.next_workspace_shell`: the primary workspace shell that holds current context, navigation, and panel areas.
- `feature.character_library_panel`: browsing and selecting character cards from the workspace.
- `feature.chat_message_rendering`: displaying stored or finalized chat messages as readable text with actions attached.
- `feature.chat_message_actions`: discovering and using actions attached to rendered chat messages.
- `feature.chat_regenerate`: re-running the current turn from the chat-options menu without re-sending the user message.
- `feature.chat_generation_auto_recovery`: bounded automatic retry behavior for visible main-chat generation failures.
- `feature.chat_recovery`: preserving and finding local edits after chat save conflicts or unconfirmed deletion, including the limits of recovery.
- `feature.character_export`: exporting the active character card as PNG or JSON with keyboard-reachable format selection and visible feedback.
- `feature.character_delete`: removing a character from the active library.
- `feature.world_info_panel`: activating global World Info and editing world-book entries from the workspace panel.
- `feature.prompt_panel`: choosing and saving prompt presets, and ordering, toggling, and editing prompt entries.
- `feature.prompt_inspector`: previewing the assembled, unsent request for the next send from the prompt panel.
- `feature.wire_log`: inspecting actual upstream requests and responses from the chat-options `链路日志` entry, initially filtered to the open conversation.
- `feature.chat_memory`: turn summaries, summary cards, and the `对话记忆` chat-options entry alongside `链路日志`, scoped to the current chat, with inherited or overridden settings, read-only summaries, turn recovery actions, and a bounded history.
- `term.character_card`: the core object users browse and operate on in the character library.
- `term.shared_browser_library`: the shared browser utilities available to workspace features.
- `page.settings`: [Settings](page.settings) is the standalone surface for provider, appearance, and advanced choices; the workspace `设置` entry opens the same surface as an overlay.

## Page States And Constraints

- **New-chat greeting state**: loading an unused character chat offers a numbered greeting picker when multiple greetings exist, and starting a new chat opens it immediately. Compact previous/position/next controls apply the adjacent valid greeting directly; a separate dropdown opens the picker. Search summaries show matching text in context, the preview stays within matching candidates, and no results disables confirmation. The picker distinguishes the current greeting from the preview and names the greeting in its confirmation action. With the picker trigger focused, `ArrowLeft`/`ArrowRight` cycle through greetings and skip empty entries; in a search or text entry those keys keep their normal cursor-editing behavior. Quick-switch controls are disabled while a greeting is being saved. Only confirming a selection or using a quick-switch control saves the greeting to the chat; cancelling writes nothing, and choosing a greeting never changes the character card. Once dialogue starts, the greeting can no longer be replaced. The selected greeting's full text survives refresh and is not overwritten when the character card is saved. The picker keeps marking the greeting that produced the first message as in use even when visible text is transformed; without that association it falls back to matching first-message text and shows `—` when no greeting matches. On narrow screens, selecting a character closes the character panel so chat controls remain reachable.
- **Settings navigation state**: the single `设置` entry opens the in-workspace [Settings](page.settings) overlay and restores the last-used tab. Direct `/settings?tab=...` remains the full-page deep-link path. Closing through the entry or Escape asks before discarding unsaved edits, including an unsaved secret draft, and only one central panel is shown at a time.
- **Shell and panel state**: the shell is not interactive while the startup overlay is visible, and becomes usable before every supporting panel has finished loading. If a supporting surface such as World Info or backgrounds fails to load, the core shell remains usable and the affected panel offers retry or later refresh. Character authoring is entered from character-library create or edit actions, not from shell navigation. World Info opens from its existing workspace entry. Opening World Info or Character Library from the shell should succeed on the first click without freezing the workspace.
- **Thumbnail state**: avatar-heavy lists can show a placeholder before thumbnails appear, reducing harsh flashes without changing page flow. Newly generated thumbnails use the shipped default quality only after a prior custom quality choice is removed and cached thumbnails are cleared. After a character image is saved, thumbnails may be prepared in the background so a later visit is less likely to stall; if that work fails, thumbnails are still generated when needed.
- **Managed media state**: uploaded images and chat attachments keep their established workspace locations and thumbnail behavior. When the managed catalog is enabled, their identity and lifecycle are preserved without changing the locations used by the workspace; when it is disabled or needs repair, the established file-backed locations remain available. An attachment whose managed location cannot be resolved is rejected before the chat is saved, instead of creating a hidden dangling reference.
- **Current-chat text maintenance state**: the open session's message text and reasoning text can be rewritten through [Character Text Replace](feature.character_text_replace) from character authoring; the action refuses to apply while a reply is generating and refreshes the current chat afterward.
- **Chat persistence state**: character chats still open, export, save, rename, delete, and import through the same workspace controls. The complete history remains available with the same message order, swipes, metadata, and row actions, and older messages load without a separate pager. Search and recent chats keep their ordering, metadata, and root-chat recent fallback. If repair or restored data is needed, the visible chat remains coherent and recovery does not expose storage controls or notices in the workspace. Out-of-band file edits do not silently replace a chat saved through the workspace.
- **Chat switching**: a library refresh or an older chat response must not change the destination of a newer selection. If loading a chat fails, saving that chat is blocked until it loads successfully on retry.
- **Chat exchange state**: Chat History import adds a history to the selected character without replacing existing chats. **Export chat with attachments (ZIP)** moves a chat and its associated managed attachments to another account; the receiving account registers those attachments before adding the chat, and unrelated files or external links are not packaged. JSONL moves history without bundling files; TXT remains a readable transcript rather than an import format. The import notice distinguishes an unreadable upload, missing JSONL chat headers, unsupported formats, and attachment references unavailable in the importing account, without claiming a rejected upload was imported.
- **Character-library state**: the library stays on the same workspace entry, with browsing, selection, and bulk actions available there; if it cannot load, a visible error explains the failure. Character creation and editing are library subflows. Deleted characters do not reappear through delayed saves or late library updates. If the library is too large to load at once, the workspace shows guidance to enable lazy character loading and restart.
- **Background and identity state**: a global active background and a chat-specific override are available; removing the override returns to the global background without opening a gallery. The workspace does not expose a global background gallery or sprite controls, and there is no persona management: user messages render under the fixed default user identity. Active backgrounds remain available through chat context and metadata.
- **Primary navigation state**: `提示词`, `角色库`, `世界书`, `正则`, and `设置` are the visible primary entries. `提示词` opens the left prompt panel and `角色库` opens the right character panel; on a first visit both side panels open and stay on wide desktop viewports, while narrow or mobile contexts show them closed, and an explicit close or unlock choice persists across reload. `设置` opens [Settings](page.settings) as an overlay on the last-used tab; direct `/settings` remains available for deep links. The shell shows only the selected assistant or character name, using `EmberDesk` for the default assistant, and does not repeat chat type, chat identifier, message count, temporary-chat state, or panel-noise copy. The active entry confirms a panel is open; errors and recovery actions stay inside that panel. Clicking the active entry closes a panel that reports itself closed and reopens it from the same entry. A panel locked open is not closed from its entry. The latest manual open and refocus choice is remembered only for the current browser page session. Entries are reachable by assistive role and name and show an active pressed state; panel activity remains local to the panel rather than global loading.
- **Main-chat state**: messages appear in order with actions for edit, copy, delete, move, and retry, and reasoning text with expand, copy, edit, delete, and collapse actions. The composer coordinates typing, selection, input-method composition, and keyboard actions; programmatic edits and completions appear in the same input, and an older asynchronous result cannot replace a newer draft. Generation handles request assembly, streaming, stop, bounded retry, fallback, and final results. Quiet and background generation produces text without a visible assistant row and does not auto-retry. Stored or finalized messages render as readable text with their actions attached. There is no separate jump-to-latest control.
- **Main-chat reading-position state**: after the user scrolls within a chat or expands older history, leaving that chat and returning in the same browser page session restores the prior reading region. If the saved anchor can no longer be reopened safely, EmberDesk falls back to the normal open result instead of leaving the chat half restored.
- **Temporary chat state**: the default Assistant can chat without selecting a character. Prompt preview, streamed replies, regeneration, and stop are available, but the conversation is not saved to chat history. A failed or stopped regeneration leaves the previous reply in place. Leaving the temporary chat stops its active reply; a brief network disconnect does not by itself stop it. After deleting the active character, the selected-character area moves to a safe empty or library state instead of reopening the deleted card.
- **World Info panel state**: global activation controls stay separate from the editor selector; empty global or editor selections must not leave stale entry content visible. Restricted character management coexists while World Info is open.
- **Group chat state**: the workspace does not expose group chats, group authoring, or multi-character generation; unsupported group requests are rejected. Existing group files on the same device are left untouched and are not auto-purged.
- **Regex editing and import state**: the Regex editor validates script name, expression syntax, content source, and timing before saving; invalid drafts stay open with inline errors. New rules start with no source selected among User message, AI reply, World Info, or Reasoning content, with chat display selected. Chat display and before-send-to-model can be selected independently without changing the saved original. Rewriting the original chat text is an explicit alternative, and existing rules keep their saved behavior. An empty replacement deletes the match; capture help is available in an expandable section. Narrow screens stack option groups and use touch-sized controls. Import shows global, preset, and character scope plus the current target, disables unavailable targets, and imports nothing on Cancel, Escape, or close. The debugger offers rule creation, disables test and ordering actions without rules, and shows output only after a test.
- **Regex workbench state**: rule lists with enable, ordering, and bulk selection; the new-script, import, debugger, and scope-authorization toolbar; and regex preset controls are all available in the same panel. Row, bulk, editor, import, and preset actions report Saved or Not saved per target, and a rejected save keeps the target label visible. Actions stay bound to the character or preset selected when they started. A failed preset application, reorder, or authorization change restores unconfirmed changes while preserving later edits and other targets. If several scopes are affected and a later one fails, earlier saved scopes remain saved; retry is per scope rather than all-or-nothing. On a failed destination write, the unpersisted rule is removed from the live list if no newer edit supersedes it, a failed preset write is not published, and the source remains available for retry. Concurrent edits are preserved; switching presets during a pending write is reported as Not saved even if the original preset is selected again.
- **Vector and token-inspection state**: the workspace does not expose vector storage, per-message prompt itemization, or a per-token probability viewer; stored itemized data remains inert. Data Bank attachment management remains available and unsupported vector requests are rejected. Request-level inspection is provided by [Prompt Inspector](feature.prompt_inspector): an unsent preview of the next request body, not message-level itemization.
- **Message rendering and generation recovery state**: when generation fails after a user message or partial output, existing messages stay readable, composer input is restored, and a local recovery action is offered instead of requiring a refresh. Visible generation retries once on the primary choice and once on an optional fallback before the manual retry control appears. Continue and swipe generation are not available. Submitting captures the message as sent; later typing remains the next draft. Macro expansion and autocomplete remain available, including variable macros, `{{//...}}` comments, and closing tags. Quiet and background generation stays non-visible and returns text without a row or retry.
- **Composer input and draft state**: the composer is a bordered, recessed input with a left-aligned placeholder. A hint line and connection-settings link appear while no model connection is available; sending while disconnected flashes the composer and warns instead of failing silently, and the stop control uses the warning color during generation. The chat-options menu offers `附加文件` alongside paste and drag-and-drop. Draft text is kept separately for each character and chat during the current page session, including when different characters have chats with the same name. Renaming a chat preserves its draft, and leaving the active chat for an empty context clears the input. Desktop Enter sends, Shift+Enter inserts a newline, and input-method confirmation does not send; mobile Enter keeps newline behavior. Repeated send clicks do not duplicate messages. Switching chats prevents pending preparation from inserting into the newly opened chat, and an older attachment operation does not remove a newly selected attachment.
- **Long-chat and mobile reachability state**: after older messages are loaded, the preserved history and message identity need no separate return-to-newest control. Composer controls, message actions, load-more, and stop or retry controls remain visible or keyboard reachable on narrow phones and wider mobile or tablet viewports without hover-only discovery. Navigation remains icon reachable without extra copy covering the composer, and the prompt panel keeps its header, presets, and scrolling body visible on a phone-sized viewport.
- **Chat management accessibility state**: Chat History is a named modal dialog with a labelled search entry; long filenames truncate within the row rather than pushing rename, export, or delete controls off-screen. Chat options use a single column of full-width actions and announce their expanded state. History and backup controls use touch-sized targets on narrow or coarse-pointer devices.
- **Send feedback**: a send immediately shows the user message and switches Send to Stop. If no reply text arrives after a short delay, the assistant row shows `等待回复…`; a fast reply skips this state. A non-streaming reply replaces it with the complete answer. Short exchanges fit without extra scrolling; longer replies open near the top so the reader starts at the beginning, including when the reply grows as it renders. If the reader has scrolled away, the workspace stays in place and offers `查看新回复` to jump to the unseen reply. If generation fails after the message was accepted, `重试` requests the reply again without resending the user message. Stopping during attachment preparation keeps the draft and selected files.
- **Options-menu regenerate state**: the chat-options menu carries a `重新生成` entry ([Chat Turn Regenerate](feature.chat_regenerate)) that is disabled while generating, editing, disconnected, or in an empty chat; availability is recomputed each time the menu opens so a stale state cannot start a second generation.
- **Backup browser state**: opening Backups shows loading, empty, or recoverable error states. View, restore, and delete show progress and prevent duplicate submissions. Backup previews and deletion confirmations are named modal dialogs with contained keyboard focus and focus restoration. Deletion names the backup file and keeps its confirmation open with an error if the request fails; restoring a backup imports it as a chat rather than deleting the current chat.
- **Chat rename and dialog state**: the rename entry is associated with its dialog heading. Blank names and failed rename requests keep the local draft visible with an inline error so the user can correct or retry. Chat-file deletion and new-chat confirmations name the action instead of generic Yes/No choices. Text, confirmation, and error dialogs keep long content scrollable while actions remain reachable; opening a dialog places focus inside, Escape cancels only the top dialog, and closing restores prior focus. Repeated confirmation while a check is pending runs it once, and a refused confirmation keeps the dialog open. Dialogs retain embedded editors, dropdowns, and image cropping; expanded editors carry the source name, focus the text area, explain that edits write through immediately, and close with Done or Escape without reverting those edits.
- **Avatar and media preview state**: avatar previews expose a named keyboard-reachable close button and an image description. Avatar cropping supports named move, shrink, enlarge, and reset actions without pointer dragging. Image previews expose a named zoom action and retain the close action when zoomed; video controls do not dismiss the preview.
- **Macro browser state**: the macro browser has a labelled search, explicit empty and no-match feedback, a clear-search recovery action, announced selected and sort states, and a readable selection state. Narrow containers stack the list and details vertically, and signatures and descriptions wrap.
- **Media and style preference state**: message rows load images, video, audio, and links directly from the location the message authors, with no per-character media gate. Only externally hosted style resources in message presentation are restricted: they stay denied unless the active character is authorized, while same-site and inline styles remain available either way. The character editor offers one authorization for those resources; it applies immediately to the open chat, persists, and leaves other characters untouched. Earlier authorizations keep working, and there is no global switch to admit or deny such resources for everyone. This authorization covers styled messages only: separate frame surfaces have their own rendering settings. First-time Creator's Notes style authorization offers two explicit scope actions; applying styles to the whole application is not a cancel action, and dismissing the question chooses the limited scope. Quota errors refer to the selected model service, not an assumed provider account.
- **Action loading state**: blocking operation dialogs announce the task name and busy state. Available stop controls are named buttons with touch-sized targets, and loading notices use the workspace theme rather than a separate bright palette.

## Navigation

- The workspace is the product's main destination and root surface.
- From this shell, users can move between the character library, chat context, and World Info without leaving [Chat Workspace](page.chat_workspace); there is no separate background-library destination.
- [Settings](page.settings) is the surface for provider, appearance, and advanced choices; the shell `设置` entry opens it as an overlay instead of leaving chat. Specialized World Info, active chat backgrounds, and avatar media remain on this workspace.
